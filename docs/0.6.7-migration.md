# Moving beskid-lings to Beskid 0.6.7

Status on branch `beskid-0.6.7` (0.6.7-preview.1): done items are marked DONE.

Workarounds that exist only because of Beskid 0.6.6. Remove each one after a
0.6.7 preview is installed and the item is confirmed.

## Runner

- DONE (preview.1). `Checker.bd`: `Invoke` runs `beskid` through `/bin/sh -c '...; echo "@exit $?"'`
  because `Process.Run` did not search `PATH` and dropped stdout on a non-zero
  exit. 0.6.7: `Process.Run("beskid", ...)` searches `PATH` and returns
  `Ok(output)` for any exit code; read `output.exitCode`. Error text comes from
  `Process.Message(error)`.
- `Editor.bd`: same `/bin/sh` use is fine (it runs a shell script on purpose).
- DONE (preview.1). `Watch.bd`: the session loop runs in a spawned fiber that `Main` joins,
  because `Channel.Receive` in `Main` returned `Closed`. 0.6.7: `Receive`
  parks in `Main`; the extra fiber can go. Check whether `Core.Process.Exit`
  after the loop is still needed for the stdin fiber.

## Known 0.6.6 bugs the exercises work around

- Generic inference from an array literal of plain numbers (ICE): `generics1`
  uses a typed array variable.
- `==` on a `for ... in` value inside a generic function: `generics1` uses an
  index loop.
- A user generic method named `Push`: `generics2` uses `Bag<T>.Add`.
- Host hooks (`startup`, `init`, `dispose`) do not run: `hosts1`/`hosts2`
  teach only compile-time wiring. When hooks run, add an exercise that uses
  an injected service.
